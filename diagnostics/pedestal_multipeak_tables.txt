PEDESTAL MULTI-PEAK -- TABLES (th210 / th220 / th230)
=====================================================
Generated 2026-07-28, REDONE 2026-07-29 on refilled inputs. Companion to
pedestal_multipeak_summary.txt (2026-07-24), which this does NOT replace: the
July note stays as the record of what was known then, including the fact that
the th210 grid had been lost.

What is new here relative to the July note:
  1. all three grids were REFILLED from the current decoded chunks and the July
     numbers reproduced;
  2. the thresholds are compared with the statistics EQUALISED, which the July
     note flagged as missing ("its 13.2% is the least comparable of the three");
  3. the provenance confound the 07-28 version of this file left open is now
     CLOSED -- see section 5.

  tallest peak: a second population below 30% of its height is not counted.


3. STATISTICS-EQUALISED COMPARISON (low gain)
--------------------------------------------------------------------------------
Method (diagnostics/compare_multipeak_stat_matched.py): only cells clearing N
entries in ALL THREE thresholds are used (identical geometry and SCA mix), and
every histogram is resampled to exactly N entries by a multinomial draw over
its own bins (identical detection power). See that file's docstring.

  N      common cells   th210    th220    th230
  200        73,466     16.98%   21.07%   13.10%
  500        56,472     17.60%   21.47%   12.59%
  1000       41,204     18.03%   21.41%   11.74%
  2000       26,834     19.15%   21.76%    9.34%

  Common-cell counts are identical to the 07-28 run on the July grids, and no
  fraction moves by more than 0.26 pp -- the same size as the 0.14 pp resampling
  noise measured there (same file in two slots: 12.78 vs 12.92% at N=500).
  Differences below ~0.3 pp are not meaningful; the ones in this table are
  5-12 pp.

Reading:
  - th220 is FLAT in N (21.1 -> 21.8%). Its 20.6% was never a statistics
    artefact: equalising does not move it.
  - th230 FALLS steeply (13.1 -> 9.3%). The gap to th220 WIDENS from 7.4 pp
    (raw) to 12.4 pp (matched). Equalising the statistics makes the difference
    bigger, not smaller -- the opposite of what the July note's caveat implied.
  - th210 sits between and rises toward th220 (17.0 -> 19.2%).


4. PER-SCA BREAKDOWN AT N=2000 (26,834 common cells, low gain)
--------------------------------------------------------------------------------
  SCA   th210   th220   th230
    0   20.8    22.7     4.6
    1   16.7    21.1    12.4
    2   18.0    19.8    22.0

  Only SCA 0-2 survive at N=2000: no cell above SCA2 has 2000 entries in all
  three. At N=500 the common set reaches SCA7 and the th220/th230 pair agrees
  from SCA2 on.

  The whole th220-th230 gap lives in SCA0 and SCA1. From SCA2 onward the
  thresholds agree. This CORRECTS the July note's explanation: it attributed
  th230's low fraction to its sample being "biased toward SCA0", which assumes
  SCA0 is intrinsically poor in multi-peaks. It is not -- th220 and th210 both
  sit near 21-23% at SCA0. SCA0 is low ONLY in th230. The sampling bias was
  real but it was amplifying an effect, not causing it.

  There is no monotonic trend with threshold: 210 -> 20.8, 220 -> 22.7,
  230 -> 4.6. th210 sits WITH th220, so th230 is the outlier rather than one
  end of a trend.


5. WHAT IS SOLID AND WHAT IS NOT
--------------------------------------------------------------------------------
SOLID -- the 7.0 ADC peak-to-peak offset. Identical in all three thresholds, on
  refilled inputs, and the distribution is DISCRETE: spikes at integer ADC
  values, not a continuum. A quantised step that does not move with the
  threshold is common-mode electronics, not a threshold effect.

SOLID (was NOT ESTABLISHED on 07-28) -- th230's SCA0 deficit is not a
  processing artefact. The 07-28 version of this file could not exclude that
  merged_th230.root, being a pre-existing file of different provenance, had
  been filled by a different code version or run selection; the old
  generated/th230 DAG did read from rundata_converted_test, the decode tree
  superseded by rundata_converted_gaudi. th230 was therefore refilled from its
  own 1,369 current chunks and scanned again:

              scanned   1pk     2pk    3+pk   MULTI-PEAK
    official   75,967   65,939  9,844   184   10,028 = 13.2%
    refilled   75,967   65,939  9,844   184   10,028 = 13.2%

  Identical in every field, down to the cell. The two merged files even have
  the same byte size (209,244,546); only their md5 differs, which is the ROOT
  header timestamp. The decode generation changes nothing, so the SCA0 deficit
  is a property of the data, not of how it was processed. The same applies to
  th220 and th210, refilled here for the same reason (section 2).

  Note the pedestal FILL code was in any case unchanged since the July grids:
  the only post-07-13 commits touching PedestalMipCalibrator (8f3c1fc, 83d0e4d)
  are MIP-fit logic. The input chunks were the only candidate difference, and
  they turn out not to matter either.

STILL NOT ESTABLISHED -- the plateau above SCA7. No common cell above SCA2 has
  2000 entries and none above SCA7 has 500, so the high-SCA end is unmeasured
  in the matched comparison.

CHOICES, NOT MEASUREMENTS -- MIN_ENTRIES=200 and threshold=0.30 are unjustified
  in the code beyond a comment. The absolute fractions (15.8 / 20.6 / 13.2%)
  depend on both. The 7.0 ADC offset does not.
